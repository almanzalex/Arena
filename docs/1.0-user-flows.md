# Arena 1.0 value flows

These flows show the product boundary directly: immutable artifacts and semantic
claims move between execution systems; Arena does not become a trainer platform,
hosted service, or credential owner.

## 1. Three-command producer → consumer handoff

```bash
python -m pip install 'arena[quickstart]==1.0.0rc1'
arena demo handoff --out ./arena-demo
arena inspect ./arena-demo/restored-policy.arena
```

Value shown: the consumer needs neither the producer's source repository nor
checkpoint loader. `source_digest` and `restored_digest` are identical, every
known-hash blob and the policy identity are verified, and interruption never
publishes a partial `arena-demo`.

Messy variants:

```bash
# Safe rerun replaces the demo through a recoverable transaction.
arena demo handoff --out ./arena-demo

# Tamper with a mirror object, then pull: Arena fails even without --verify because
# content-addressed bytes are always hashed.
arena pull 'file:///…#sha256:…' --out ./tampered
```

## 2. One semantic evaluation across three bindings

From this checkout with `openenv`, `gimitest`, Torch, and PettingZoo installed:

```bash
python -m venv /tmp/arena-gimitest
/tmp/arena-gimitest/bin/python -m pip install 'arena[torch,pettingzoo,gimitest]==1.0.0rc1'
/tmp/arena-gimitest/bin/python -m pip install --no-deps gimitest==1.0
export ARENA_GIMITEST_PYTHON=/tmp/arena-gimitest/bin/python
arena doctor --capability gimitest
python examples/1.0/run_local_boundaries.py --out ./arena-1.0-boundaries
```

The script launches a real separate OpenEnv loopback service, pins its schema,
proves trace equivalence to the native task, and obtains one verified task-intent
digest. It then evaluates the same policies and seeds through:

```text
native task ───────┐
OpenEnv service ───┼─ same evaluation intent ─ same semantic result
Gimitest worker ───┘                         └ distinct binding digests
```

Every cell uses a supervised process with a hard wall-time budget. A fourth,
non-no-op Gimitest scenario flips rewards and must change both the evaluation
intent and semantic result digests, proving the provider hook actually ran.

Value shown: a lab can change runtime/provider infrastructure without changing
what it claims to evaluate. Conversely, a semantic intervention cannot hide
behind the same result identity.

## 3. Immutable remote handoff

```bash
arena doctor --capability hf
arena push policy.arena 'hf://models/ORG/REPO/arena?revision=main' --verify
arena pull 'hf://models/ORG/REPO/arena?revision=<commit>#sha256:…' \
  --out restored.arena --verify
```

Arena resolves movable Hugging Face refs once and uses the returned immutable
commit for both descriptor and blobs. The URI returned by push contains that
commit. Local `?simulate=/absolute/path` is useful for workflow rehearsal but is
recorded as simulation and never satisfies the live 1.0 release gate.

## 4. Third-party extension without a core fork

```bash
python -m pip install ./examples/plugins/arena-example-store
arena push policy.arena example:///tmp/arena-example --verify
python -m pip uninstall -y arena-example-store
arena doctor --capability core
```

The wheel registers `external_store:example` under `arena.plugins.v1`. It is not
imported during core startup, and uninstalling it leaves core usable. A plugin
can produce local qualification evidence; it cannot declare itself release
stable.

## 5. Failure is a result, not missing data

An evaluation with `budgets.executor: process` and a tiny timeout records:

```json
{
  "schema": "arena.eval-run/v1",
  "state": "failed",
  "denominators": {"attempted": 1, "completed": 0, "failed": 1}
}
```

`arena eval report` refuses it unless the semantic suite explicitly declares
`failure_policy.missingness: allow` and a sufficient
`max_failed_episodes`. The CLI exits 6 with an `arena.diagnostic/v1` repair.

## 6. Public-repository producer, source-free consumer

The release proof pins CleanRL at
`fe8d8a03c41a7ef5b523e2e354bd01c363e786bb`, trains its CartPole DQN, and
exports the resulting Q-network through the existing BYO TorchScript surface:

```bash
python examples/1.0/export_cleanrl_cartpole.py \
  --cleanrl-checkout /path/to/pinned/cleanrl \
  --checkpoint /path/to/dqn.cleanrl_model \
  --out ./cleanrl-cartpole.arena
arena policy verify ./cleanrl-cartpole.arena
```

The exporter-side bridge reproduces the upstream network's exact named layers;
strict state-dict loading rejects drift. Reference actions and logits are
captured from the live pre-script module and recorded as source-conformance.
The consumer does not import CleanRL or the bridge.

The messy release rehearsal also covers a useful real-world failure: the pinned
CleanRL run successfully wrote its checkpoint and then exited nonzero because
its optional video-evaluation dependency (`moviepy`) was absent. Arena consumed
the already-published checkpoint without pretending the trainer's later failure
did not happen.

## What these flows deliberately do not claim

- Loopback OpenEnv and local HF simulation prove contracts, not live release
  availability.
- Process isolation controls failure and resources; it is not a malware sandbox.
- Detached signatures prove possession of a trusted key; Arena does not supply a
  certificate authority, revocation service, or publisher account.
- The frozen OpenSpiel cases and categorical offline trainers are qualified
  cases, not universal game or training support.
