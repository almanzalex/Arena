# Arena 0.5 — generalization without universal claims

**Status:** Implemented on `codex/0.5-generalization`; local release verification
recorded in [0.5-evidence.md](0.5-evidence.md).

0.5 turns the narrow 0.4 pilots into extension seams and proves each seam with at
least one materially different case. Support remains qualification-scoped: a
registry entry plus executable evidence is a claim; resemblance to a qualified
case is not.

| Gate | General contract | Independent evidence |
|---|---|---|
| G-01 | Trainer registry dispatches algorithms without CLI/core branching | Behavior cloning and return-weighted regression learn different qualified objectives |
| G-02 | Portable datasets have deterministic digest-bucket splits | Repeated materialization gives the same identity and split assignment |
| G-03 | Training resumes exactly from a mutation-checked checkpoint | Interrupted 20→40 epochs equals uninterrupted 40 epochs; changed/tampered state is refused |
| G-04 | Dynamic agents resolve through declared lifecycle strategies | Exact-agent and stable-role resolvers; removal/re-entry and joint leave/join preserve segments |
| G-05 | OpenSpiel dispatches by semantic family | Sequential perfect information, explicit chance/imperfect information, and simultaneous play |
| G-06 | External task/provider dependencies cross explicit boundaries | Second typed OpenEnv task over the real WebSocket service; optional separate-Python Gimitest worker |
| G-07 | Every store can produce comparable qualification evidence | `arena store qualify` records backend, simulation/live mode, immutable URI, and restored identity |
| G-08 | Authenticity is independent of storage location | Detached user-owned Ed25519 signature verifies after all four credentialed-store simulations |
| G-09 | Evaluation workers perform real parallel cell execution | One-worker and multi-worker results retain stable cell/seed order |
| G-10 | The boundaries compose as one user journey | `tests/acceptance/test_boundary_demo.py` |

## Executable user flows

### 1. Collect, split, train, resume, and reuse

```bash
arena data select teacher-run --role player_0 --out selected
arena data materialize selected/dataset.yaml --out portable \
  --split train=.8 --split validation=.2 --split-seed 17
arena train stage-1.yaml --out stage-1
# Set resume_from: stage-1 and a larger epochs value in resumed.yaml.
arena train resumed.yaml --out resumed
arena policy verify resumed/policy.arena
```

The training contract covers algorithm/config, dataset/split, role, spaces,
architecture, preprocessing, seed, batch size, learning rate, and weighting.
Changing any of these makes resume fail before output is published. Checkpoint
payloads load with `weights_only=True` and are digest-checked first.

### 2. Run a changing population without per-agent policy duplication

Use `interaction: dynamic_aec` and a role resolver:

```yaml
lifecycle:
  resolver:
    kind: role
    agent_roles:
      agent_0: contestant
      agent_1: contestant
      agent_2: contestant
    join_eligibility:
      contestant: [sha256:...]
```

Assignments contain one `contestant` policy. A concrete agent may leave and later
rejoin, but every join repeats eligibility and composition checks and resets policy
state. The trajectory retains all segments rather than overwriting the first one.

### 3. Qualify a game semantic family

```bash
arena task verify-equivalence examples/tasks/openspiel-kuhn-poker.yaml \
  --trace-suite examples/tasks/openspiel-kuhn-poker-trace.yaml
arena task verify-equivalence examples/tasks/openspiel-leduc-poker.yaml \
  --trace-suite examples/tasks/openspiel-leduc-poker-trace.yaml
arena task verify-equivalence examples/tasks/openspiel-matrix-rps.yaml \
  --trace-suite examples/tasks/openspiel-matrix-rps-trace.yaml
```

`kuhn_poker` and `leduc_poker` prove explicit chance-node handling and
information-state observations. `matrix_rps` proves simultaneous joint actions.
Unknown game IDs and semantic mismatches are refused; a new game becomes supported
only after adding a catalog declaration and frozen trace.

### 4. Qualify storage and preserve authenticity

```bash
arena attest keygen --private lab-private.pem --public lab-public.pem
arena attest sign policy.arena --key lab-private.pem \
  --issuer example-lab --out policy.attestation.json
arena store qualify policy.arena \
  'hf://models/example/arena?simulate=/tmp/hf-mirror' \
  --out hf-qualification.json
arena pull 'hf://models/example/arena?simulate=/tmp/hf-mirror#sha256:…' \
  --out restored.arena --verify
arena attest verify restored.arena policy.attestation.json --key lab-public.pem
```

Simulation rehearses the Arena mirror protocol, not provider availability. The live
smoke in `examples/boundaries/live_store_smoke.py` refuses simulation URIs.

### 5. Run the composed journey

```bash
bash examples/boundaries/run_demo.sh
```

It executes role-based lifecycle re-entry; twelve-episode collection; deterministic
splits; checkpoint resume and reuse; one game in each OpenSpiel semantic family;
detached signing; and verified HF/OCI/W&B/MLflow simulations.

## Deliberate product boundary

Arena owns portable identities, contracts, qualification, lineage, deterministic
orchestration, and failure evidence. It does not own upstream environment catalogs,
trainer frameworks, provider services, credential systems, billing, dashboards, or
key trust infrastructure. Those boundaries keep the offline core useful and prevent
the project from becoming a shallow replacement for mature systems.

Unknown cases fail with an extension recipe. New implementations register behind the
existing trainer, lifecycle-resolver, task-packager, interaction, eval-provider, or
store interfaces and bring their own qualification fixture.
