# RLX 1.0 readiness ledger

0.5 is the feature-generalization milestone. 1.0 should be a reliability and claim
closure release, not another scope expansion. The default answer to new surface area
before these gates close is “use the registry and qualify it,” not “add it to core.”

## What 0.5 removes

| Former limit | 0.5 disposition |
|---|---|
| One training algorithm hard-coded in runtime | Trainer registry plus two distinct qualified cases |
| Dataset copied but not split reproducibly | Deterministic, identity-bearing digest-bucket splits |
| Training could not resume exactly | Contract-bound, payload-verified optimizer/model/RNG checkpoint |
| Dynamic policy assignment duplicated per agent | Stable-role lifecycle resolver |
| Reused agent IDs lost prior lifetime evidence | Ordered segment history |
| OpenSpiel meant deterministic sequential only | Explicit chance/imperfect-information and simultaneous interaction families |
| OpenEnv claim rested on one scalar RPS task | Second typed Box task and pinned capability contract |
| Gimitest dependency conflict shared the core interpreter | Optional separate-Python subprocess boundary |
| Evaluation `workers` was not real concurrency | Concurrent independent cells with deterministic output order |
| Backend tests were structurally different | One store-qualification report across registered schemes |
| Digests proved integrity but not publisher authenticity | Detached user-owned Ed25519 attestation |

## Limits intentionally left

These are product boundaries, not incomplete 0.5 work:

- RLX does not host accounts, artifacts, credentials, billing, dashboards, or a
  public catalog.
- RLX does not replace OpenEnv, OpenSpiel, Gimitest, Hugging Face, ORAS, W&B, or
  MLflow. It pins and verifies adapters to them.
- RLX does not infer lifecycle assignments or trust. Policy eligibility and trusted
  signing keys remain explicit inputs.
- Ed25519 attestations do not provide a certificate authority, revocation,
  transparency log, hardware-key integration, or malware sandbox.
- Training cases are offline categorical reference implementations, not a universal
  distributed/online RL trainer. Online environment collection, replay, distributed
  learners, and arbitrary optimizer graphs belong behind new trainer cases.
- OpenSpiel support is per qualified game ID within implemented semantic families,
  not every game in the upstream catalog.
- Individual materialized episodes are verified JSON files. Large-scale streaming,
  sharding, compression, and object-store-native datasets remain unclaimed.
- Numerical reproducibility is scoped to declared seeds/contracts and supported
  tolerances, not bit identity across arbitrary accelerators and library versions.

## Required before a 1.0 tag

| ID | Release gate | Completion evidence |
|---|---|---|
| R-01 | Linux and macOS fast CI green from a clean checkout | Linked CI runs for the release commit |
| R-02 | Wheel/sdist build and network-disabled wheel handoff green | Hermetic CI artifact plus `pytest -m slow` output |
| R-03 | A real second user completes policy and evaluation handoff docs | Signed records in the existing usability templates |
| R-04 | Each credentialed store claimed for 1.0 has a recent live round trip | `rlx.store-qualification/v1` report with `mode: live`; otherwise mark that backend preview |
| R-05 | OpenEnv tested against a separately deployed service, including disconnect/timeout/crash drills | Qualification reports and failure run records |
| R-06 | Gimitest tested in a genuinely separate compatible virtualenv | Subprocess qualification with a non-core interpreter path |
| R-07 | Large/messy corpus soak covers interruption, duplicate content, empty splits, corrupted episodes, and concurrent eval | Checked soak report with resource envelope |
| R-08 | Dependency/security review covers optional execution and signing paths | Dependency lock/SBOM, secret scan, and explicit trusted-code documentation |
| R-09 | Schemas receive compatibility/migration policy | Version matrix and fixtures loading the oldest promised 1.x artifact |
| R-10 | Performance budgets are rerun on both reference platforms | Updated overhead report with regression thresholds |

## Live-store command

```bash
python examples/boundaries/live_store_smoke.py policy.rlx \
  hf://models/ORG/REPO/rlx --out /tmp/restored-live.rlx
```

Repeat for each backend intended to be called stable. A failed or unavailable
provider does not invalidate the offline core; it changes that adapter's release
label.

## 1.0 decision rule

Tag 1.0 only when R-01 through R-10 have attached evidence or an explicit,
documented downgrade of the affected claim. Do not convert a missing external
credential or upstream service into a fake local proof.
