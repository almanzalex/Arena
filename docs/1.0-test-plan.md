# RLX 1.0 adversarial test plan

This plan proves the promises in `docs/1.0-readiness.md`. Every case produces a
machine-readable record with the release commit, fixture seed, platform,
dependency set, command, duration, resource measurements, result digest, and
diagnostic code when failure is expected.

## Test layers

| Layer | Purpose | Trigger |
|---|---|---|
| Unit/contract | Schema, identity, validation, and error invariants | Every change |
| Integration/subprocess | Real files, processes, threads, and local protocols | Every pull request |
| Hermetic handoff | Built wheel with source tree absent and network disabled | Every release candidate |
| Live qualification | Real external runtime/provider/store | RC and on a freshness schedule |
| Chaos/soak/performance | Interruption, scale, leaks, and budgets | Nightly plus RC |
| Human usability | First-use and cross-user handoff | RC |

All random generation uses a recorded seed. A failure must print the seed and
preserve the smallest reproducible fixture. Expected failures pass only when the
diagnostic code, cleanup state, and repair text also match.

Release-critical cases run on every RC and are a compact deterministic proof of
each invariant. Extended cases run nightly and again on the RC: T-201 at full
50,000-episode scale, the million-member/archive-expansion variants of T-907,
T-401 at 100 reentries, T-507 at 100 schedules, the full T-1200 soak, and U-05's
public clone. Pull requests run reduced fixtures that exercise the same branch.

## Global invariants

- A content digest changes if and only if identity-bearing content changes.
- An invalid or partial output is never accepted by `inspect`, `verify`, or a
  downstream consumer.
- Retrying an idempotent operation produces the same final identity.
- Worker count, scheduling, and input enumeration order do not change semantic
  output.
- Unsupported inputs fail before unsafe execution.
- Credentials, signing secrets, and canary tokens never appear in output.
- All children, threads, descriptors, locks, and staging directories are gone
  after success, expected failure, timeout, or cancellation.

## T-1050 Out-of-tree registry plugin

Build and install a tiny independent plugin wheel exposing one provider or store
entry point. Invoke it through the normal CLI without application-side
registration, qualify it, and prove the source artifact identity is unchanged.
Then test built-in-name collision, registration failure, unsupported protocol
version, lazy non-use, and uninstall. Also make it hang on import, print to stdout,
mutate global state, register two names, disappear during a process, leave a stale
discovery cache, and attempt to mark itself stable using only local qualification.
Core startup and offline flow must continue to work before use, after a failed
plugin, and after uninstall; JSON stdout cannot be polluted.

## T-1200 Performance and soak

Reference stress:

- materialize and verify 50,000 deterministic episodes;
- evaluate the reference suite with 32 workers;
- perform 1,000 push/pull/verify cycles against `file://`;
- execute 10,000 dynamic lifecycle segments;
- repeat timeout/cancellation drills 100 times.

Measure wall time, CPU time, peak resident memory, file descriptors, process/thread
counts, temporary bytes, and p50/p95 operation latency. On the same runner and
fixture, median overhead may regress at most 15% and p95 at most 20% from the
checked baseline. Correctness, cleanup, and integrity have zero tolerance.
The loopback OpenEnv reference also has a 5 ms median/10 ms p95 absolute ceiling
per reset plus one joint RPS step. `inspect` and `verify` each have a 2-second
ceiling for the checked reference bundle.

## T-1300 Human value flows

### U-01 Producer to consumer

Producer on machine A installs the RC, builds and signs a policy, pushes it, and
sends only the URI, expected digest, trusted public key, and quickstart. Consumer
on machine B installs from the public index, pulls with `--verify`, inspects
lineage, and reproduces the declared evaluation. Record time-to-first-verified
artifact, every hesitation, help request, and unexpected command.

### U-02 Native to external equivalence

A user imports a task, runs one policy/eval definition natively and through a
separate OpenEnv service, and reads either a passing trace comparison or the first
divergent step. Include one intentional schema mismatch and one tolerance miss so
the repair path is tested, not merely documented.

### U-03 Provider and store swap

A user switches the eval provider and store URI without rebuilding the policy.
They verify that lineage points to the same source identity and that the
capability label/evidence is visible before credentials are used.

### U-04 Interruption and recovery

Terminate training after a checkpoint and interrupt a pull during blob two. The
user resumes training exactly, observes that no partial pulled artifact is valid,
retries, and gets the expected final digest.

Repeat the packaged quickstart after interruption in the same directory and run it
concurrently in two terminals. It must resume/idempotently replace or report an
explicit conflict without mixing results.

### U-05 Public-repository producer

Clone CleanRL commit `fe8d8a03c41a7ef5b523e2e354bd01c363e786bb`
in an isolated environment, train the CartPole DQN fixture, export the learned
categorical actor and a source-captured reference suite through the stable RLX
BYO-module API, then delete the CleanRL checkout. A consumer in a clean RLX
environment verifies, loads, and runs the reference suite. Record the upstream
commit, checksum-verified source archive, license, bounded CPU training seed,
producer-side trusted checkpoint handling, exporter digest, and final RLX policy
digest. Nightly/RC runs may use the network; normal pull requests use the archived
fixture.

### U-06 Integration author

A non-author builds the canonical `rlx-example-store` as a separate wheel using
entry-point group `rlx.plugins.v1`, installs it, sees it in `rlx doctor`, runs
`rlx store qualify`, uses it without changing source artifact identity, and
uninstalls it. They must correctly distinguish local qualification from RLX
release-stable status and complete the flow using only `docs/plugin-authoring.md`.

Human acceptance:

- at least two non-author participants cover Linux x86_64 and macOS arm64;
- timer starts before the documented install command; cold install,
  installed-to-first-verified-artifact, and total demo time are recorded
  separately;
- first local verified artifact and complete local demo each finish within five
  minutes after installation on a prepared supported machine;
- a real producer and consumer use different machines/accounts;
- both cross-machine handoffs complete from docs without source-code help;
- no verbal help or repository access; documented repair is allowed, undocumented
  intervention fails;
- prescribed command typo, missing extra, wrong key, stale schema, and unavailable
  service each communicate problem, cause, and repair;
- participant identifies stable/preview and live/simulated before credentials;
- no participant mistakes preview for stable or simulated evidence for live.

The R-03 record includes the terminal transcript, exact docs/package versions,
artifact hashes, timers, and every intervention. A CLI or quickstart-doc change
invalidates and repeats the affected run. Diagnostics remain self-sufficient if
their documentation URL is unreachable.

## Mutation checks

For the highest-risk invariants, CI must prove the test can fail by running small
mutants:

- skip OpenEnv re-pin;
- write mirror output directly to final;
- accept an extra agent key;
- publish store descriptor before the final blob;
- omit subprocess digest correlation;
- suppress timeout cleanup;
- import from checkout instead of wheel.

The gate is invalid if its corresponding mutant survives.

## Release-candidate run order

```text
contract/unit
  -> integration/subprocess
  -> build exact artifacts
  -> source-free hermetic/platform
  -> security corpus
  -> chaos/soak/performance
  -> live qualifications
  -> human handoffs
  -> evidence verify
  -> publish candidate and repeat clean install
```

Failures invalidate their gate and every downstream record tied to a changed
artifact. Unaffected live evidence may be retained only if the evidence schema
declares it independent of the changed component and `release verify` agrees.
